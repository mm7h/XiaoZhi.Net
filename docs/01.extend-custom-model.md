## 如何扩展自定义模型

#### 步骤 1：准备模型文件目录

在 `models` 目录下，根据模型类型（`asr` / `tts` / `vad`）找到对应的子目录，在其中新建一个以 **kebab-case** 命名的模型文件夹，并将模型所需的资源文件放入其中。

> 例如，扩展一个名为 `MyCustomTTS` 的 TTS 模型，需创建以下目录结构：
> ```
> models/
> └── tts/
>     └── my-custom-tts/   ← 文件夹名称须为 kebab-case 格式
>         └── model.onnx   ← 模型文件统一命名为 model.onnx（如适用）
> ```

#### 步骤 2：实现模型提供者类

在 `XiaoZhi.Net.Server` 项目中，对应模型类型下的 `Providers` 目录内新建实现类。

- **通用模型**：直接实现 `XiaoZhi.Net.Server.Providers` 命名空间下对应的接口（如 `ITts`、`IAsr`、`IVad`），并重写全部约定成员。
- **Sherpa-onnx 模型**：可直接继承对应类型的 `BaseSherpaTts<T>` / `BaseSherpaAsr<T>` / `BaseSherpaVad<T>` 抽象基类，框架已封装好推理调用与生命周期管理，只需在 `Build` 方法中完成模型配置即可。

以 `Sherpa-onnx` 的 `TTS` 模型为例（基于 `BaseSherpaTts<T>`）：

```csharp
internal class MyCustomTTS : BaseSherpaTts<MyCustomTTS>, ITts
{
    public MyCustomTTS(IAudioEditor audioEditor, ILogger<MyCustomTTS> logger)
        : base(audioEditor, logger) { }

    public override string ModelName => nameof(MyCustomTTS);

    public override bool Build(ModelSetting modelSetting)
    {
        try
        {
            if (!this.CheckModelExist()) return false;

            var config = new OfflineTtsConfig();
            // 在此配置模型路径及参数...
            config.Model.YourModel.Model = Path.Combine(this.ModelFileFolder, "model.onnx");

            this.Build(config, modelSetting);
            return true;
        }
        catch (Exception ex)
        {
            this.Logger.LogError(ex, "Failed to build MyCustomTTS.");
            return false;
        }
    }
}
```

#### 步骤 3：在 `ProviderManager` 中注册模型

在 `ProviderManager.cs` 对应的 `RegisterXxx` 方法中，按模型类型将新实现类注册到 DI 容器，并在 `switch` 分支中添加对应的 kebab-case 模型名称：

```csharp
// 以 TTS 为例，在 RegisterTts 方法中添加：
case "my-custom-tts":
    services.AddKeyedSingleton<ITts, MyCustomTTS>(key);
    break;
```

#### 步骤 4（仅 Sherpa 模型需要）：将模型名称注册至 `SherpaModels`

若新模型基于 `sherpa-onnx` 实现，还需将其类名添加到 `SherpaModels.cs` 中对应的模型列表，以便框架正确识别其为 Sherpa 模型并在启动时自动完成预构建：

```csharp
// SherpaModels.cs
public static string[] TtsModels = [nameof(Kokoro), nameof(MyCustomTTS)];
```

#### 步骤 5：更新 `config.json` 配置

在 `configs/config.json` 中，将对应类型的 `SelectedSettings` 值设置为新模型名称，并在 `ConfiguredSettings` 中补充所需的配置项：

```json
{
  "SelectedSettings": {
    "TTS": "MyCustomTTS"
  },
  "ConfiguredSettings": {
    "TTS": {
      "MyCustomTTS": {
        "SpeechRate": "1.0",
        "SpeakerId": "0"
      }
    }
  }
}
```
## 流式 ASR 配置

客户端通过 hello.audio_params 声明的 sample_rate、channels 和 frame_duration 仍保存在会话的 AudioSetting 中，用于初始化 Opus 解码器和输入重采样器。服务端内部的 VAD 与 ASR 始终消费 **16 kHz、16-bit、单声道 PCM**；支持的客户端 Opus 输入采样率为 8/12/16/24/48 kHz，声道必须为单声道。

火山引擎流式 ASR 可选择 HuoshanUnidirectional（bigmodel_nostream）或 HuoshanBidirection（bigmodel_async）。两者需要 ApiKey + ResourceId，也兼容 AppId + AccessToken + ResourceId；音频自动使用内部 16 kHz PCM 分包上传。

阿里云实时 ASR 使用配置名 AliyunRealtime，默认模型为 qwen-audio-3.0-asr-flash-streaming，也支持 fun-asr-realtime。必须填写 ApiKey；Region 可选 cn-beijing 或 ap-southeast-1，若已开通百炼专属推理可填写 WorkspaceId，或直接提供 Endpoint 覆盖默认 WebSocket 地址。中间结果只在 Provider 内部合并，任务结束后的最终文本才会进入现有对话流程。
