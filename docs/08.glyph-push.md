# 设备缺字补充 ✍️

上一篇：[07-Function Tool 扩展](07.function-tools.md)<br />

## 🤔 为什么有些字显示不出来？

小智设备的存储空间有限，通常只带了一部分常用字。遇到字库里没有的字时，屏幕上就可能出现空白或方框。

服务端补字（Glyph Push）就是：**设备缺哪个字，服务器就把这个字的显示数据随文字一起发过去，让设备能把它画出来。**

比如，回答中有一个设备没有收录的生僻字。只要设备支持补字，而且服务器的字体包里有这个字，就可以补上。设备原本能显示的字继续使用自己的字库。

这只影响屏幕上的文字显示，不会改写对话内容，也不会改变语音识别或语音播放。

## ✅ 使用前需要准备什么？

- **设备支持补字。** 需要使用支持 Glyph Push 的小智固件和配套字体资源。设备连接时会自动告诉服务器自己是否支持，无需手动填写设备参数。
- **服务器准备好字体包。** 字体包放在服务器上，供服务器按需取字，不需要把整包刷进设备。
- **字体配置指向正确的文件。** 服务器需要通过 `manifest.json` 找到字体包里的字。

> 💡 旧固件或某些自定义主题可能不支持补字。升级服务器并不会自动让这些设备获得补字能力；设备仍可照常对话，只是缺字问题可能继续存在。

## 📦 使用 Release 运行包

GitHub Actions 生成的新运行包会自动下载并带上字体资源，Windows、Linux 的 x64 和 ARM64 包使用同一套字体。

解压运行包后，确认有下面这个文件：

```text
server/
├── XiaoZhi.Net.Sample.Server（Windows 下带 .exe）
├── Configs/
│   └── config.json
└── fonts/
    └── noto-v1-full/
        ├── manifest.json
        ├── 14_1/
        ├── 16_4/
        ├── 20_4/
        └── 30_4/
```

保持默认配置，并从 `server` 目录启动主服务即可。使用运行包附带的 Docker 部署方式时，字体也会复制到主服务镜像中。

> 📌 这里指包含本次更新的新运行包。以前下载的旧包不会自动增加字体，需要重新下载新包，或按下一节手动补上。

## 🛠️ 自己运行源码，或给旧运行包补上字体

### 1. 下载并解压字体

下载 [fonts.zip 字体包](https://github.com/mm7h/XiaoZhi.Net/releases/download/resources/fonts.zip)，解压后会得到 `noto-v1-full` 文件夹。

把这个文件夹放进主服务的 `fonts` 文件夹里：

- 使用运行包：放到 `server/fonts/noto-v1-full/`。
- 运行本仓库示例源码：放到 `demo/XiaoZhi.Net.Sample.Server/fonts/noto-v1-full/`。该目录下的字体会随示例项目构建和发布一起复制。

请保留整个文件夹，**不要只复制 `manifest.json`**，也不要多套一层 `fonts`。`manifest.json` 相当于字体的目录，真正用来显示文字的文件在它旁边的几个子文件夹中。

### 2. 检查配置

在你实际使用的 `config.json` 中，找到下面这一段。它和 `LogSetting` 等配置处于同一层：

```json
"GlyphPushSetting": {
  "ManifestPath": "./fonts/noto-v1-full/manifest.json"
}
```

`ManifestPath` 就是字体目录文件的位置。上面的默认写法表示：从**启动程序时所在的目录**进入 `fonts/noto-v1-full`，读取 `manifest.json`。它不是相对于 `config.json` 所在的目录。

如果从其他目录启动程序，可以改成完整路径，例如：

```json
"GlyphPushSetting": {
  "ManifestPath": "D:/XiaoZhi/server/fonts/noto-v1-full/manifest.json"
}
```

Linux 下可以使用 `/opt/xiaozhi/server/fonts/noto-v1-full/manifest.json` 这样的完整路径。Docker 中请填写容器内能访问的路径，运行包默认是 `/app/fonts/noto-v1-full/manifest.json`。

### 3. 重启并试一试

保存配置后重启服务器，让设备重新连接，再试一条以前会缺字的对话。服务器会在发送识别文字和回复字幕时，自动附上能补充的字。

想核对连接消息时，可以查看设备的 `hello`：其中 `features.glyph_push` 为 `true`，并带有 `text_font`，才表示设备已启用补字。这些内容由设备发送，不需要在服务端配置中手填。

## 🔎 还是显示空白，先检查这些

| 遇到的情况 | 可以怎么做 |
| --- | --- |
| 配置字体后服务器初始化失败 | 检查文件是否存在、路径是否正确，以及服务器是否有读取权限。配置了无效的字体路径会导致初始化失败。 |
| 字体已经放好，设备仍然缺字 | 确认设备固件和主题支持补字。旧固件或缺少配套字体信息的自定义主题可能不会启用这项能力。 |
| 只有部分字仍然显示不出来 | 字体包并不包含所有文字和 emoji；包里没有的字无法补上。 |
| 修改了设备字体后失效 | 服务端字体必须和设备使用的字体版本、字号及显示规格匹配。不要把普通 TTF 字体直接替换进来。 |

当前提供的字体包是 `noto-v1`，包含 14、16、20、30 四种字号及其对应的显示规格；设备会自行报告它需要哪一种。服务器找不到匹配资源时，会继续发送原本的文字，不会强行使用其他字体替代。

暂时不需要补字时，可以把 `ManifestPath` 设为 `null`：

```json
"GlyphPushSetting": {
  "ManifestPath": null
}
```

保存并重启后，服务器就不再加载补字字体包。
